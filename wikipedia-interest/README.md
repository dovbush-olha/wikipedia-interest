# wikipedia-interest

Навичка для AI-агента у форматі [Agent Skills](https://agentskills.io/specification).
Вона оцінює відносну увагу до однієї теми в кількох мовних розділах Wikipedia за статистикою переглядів і готує звіт на одну сторінку PDF.
Навичка допомагає засновникам B2C-продуктів вирішити, які теми й мовні аудиторії досліджувати далі.

Приклади запитів:

- «Порівняй зростання інтересу до інтервального голодування в польськомовній та чеськомовній Wikipedia за останні два роки.»
- «Ми думаємо додати курс з астрономії до освітнього застосунку. Чи зростає інтерес до цієї теми в україномовній Wikipedia, і наскільки цьому зростанню можна довіряти?»
- «Ми створюємо застосунок для вивчення мов. Порівняй інтерес до вивчення англійської у вибраних нами мовних розділах та підготуй короткий звіт: які аудиторії варто дослідити наступними й чому?»

Навичка розрахована на швидку дешеву модель: повний сценарій перевірено на Claude Haiku 4.5.

## Встановлення

Потрібні Node.js 24.12 або новіший і доступ до `wikipedia.org`, `wikidata.org` і `wikimedia.org`.
Node запускає TypeScript напряму, тож збірки немає.

1. Скопіюйте теку `wikipedia-interest/` туди, де ваш агент шукає навички.
   Для Claude Code це `~/.claude/skills/wikipedia-interest/` (для всіх проєктів) або `.claude/skills/wikipedia-interest/` у проєкті.
   Тека також є single-skill плагіном Claude Code, тож її можна підключити на одну сесію: `claude --plugin-dir <шлях>/wikipedia-interest`.
2. Встановіть залежності в теці навички:

   ```
   cd <шлях>/wikipedia-interest
   npm ci
   ```

   `.npmrc` вмикає `engine-strict`, тож на старішому Node `npm ci` одразу падає з `EBADENGINE`.
   Якщо цей крок пропущено, агент сам запустить `npm ci`, щойно побачить помилку `Cannot find package`.

## Використання

### Через агента

Поставте агенту питання своїми словами, українською чи англійською.
Агент сам обере тему, мовні розділи й період, запустить аналіз, напише короткий висновок і згенерує PDF.
Відповідь у чаті закінчується рядком `PDF: <шлях>`.
Результати кожного аналізу лежать у новій теці `wikipedia-interest-runs/<тема>-<мови>/` у поточній робочій директорії: `analysis.json`, `conclusion.json` і `report.pdf`.

Що варто знати:

- Один аналіз - одна тема і до 3 мовних розділів: більше не вміщається на одну сторінку.
  Для більшої кількості мов агент попросить скоротити список, а не відкине мови сам.
- Період за замовчуванням - останні 24 завершені місяці; можна попросити довший («за 5 років») або з конкретного місяця («з березня 2022»), але не коротший за 24 місяці.
- Якщо назва теми неоднозначна («Mercury»), агент обере значення з контексту питання або перепитає.
- Якщо точної статті немає («вивчення англійської»), агент виміряє близьку тему («англійська мова») як проксі, і звіт явно назве це припущенням.
- Уточнення на кшталт «а тепер додай словацьку» перезапускають аналіз з новими аргументами; відповіді Wikimedia кешуються в `.cache/` теки навички, тож повторні запуски швидкі.

### Напряму з командного рядка

Агент виконує ті самі дві команди, які можна запустити й вручну:

```
node <шлях>/wikipedia-interest/scripts/analyze.ts \
  --topic "Astronomy" --topic-lang en --langs uk,pl --months 24 --report-lang uk \
  --user-question "Чи зростає інтерес до астрономії?" --out-dir runs/astronomy
```

`analyze.ts` друкує компактний JSON з метриками і записує повний `runs/astronomy/analysis.json`.
Далі потрібен `runs/astronomy/conclusion.json` з інтерпретацією без чисел:

```json
{
  "summary": "Відносна увага до астрономії знизилась в обох розділах.",
  "languages": [
    { "lang": "uk", "action": "lower_priority", "rationale": "Стійке зниження відносної уваги з високою надійністю." },
    { "lang": "pl", "action": "lower_priority", "rationale": "Зниження відносної уваги з помірною надійністю." }
  ]
}
```

```
node <шлях>/wikipedia-interest/scripts/report.ts --run-dir runs/astronomy
```

`report.ts` перевіряє `conclusion.json` відносно `analysis.json` і створює `runs/astronomy/report.pdf`.
Повний опис аргументів, статусів і правил висновку - у [SKILL.md](SKILL.md).

## Терміни звіту

- **Відносна увага** - частка переглядів статті людьми в усіх переглядах людьми її мовного розділу.
  Це частка уваги всередині Wikipedia, а не кількість зацікавлених людей, ринковий попит чи готовність платити.
  Навичка вимірює її, а не сирі перегляди, бо загальний трафік Wikipedia зараз падає в усіх перевірених розділах (uk приблизно на 28% за рік).
- **Переглядів на мільйон** - медіана відносної уваги за останні 12 місяців: скільки переглядів статті припадає на мільйон переглядів розділу.
- **Зміна відносної уваги** - зміна медіани останніх 12 місяців запитаного періоду відносно медіани перших 12 місяців.
  Це не «зростання за N років» і не середньорічне зростання; які саме місяці порівнюються, звіт пише явно.
- **Місяців зростання** - скільки з останніх 12 місяців мають відносну увагу вищу, ніж той самий місяць роком раніше.
- **Надійність тренду** - проста продуктова евристика `heuristic_v1` за стабільністю останніх 12 місяців і якістю даних, а не статистична довіра.
- **Виміряна тема** - один елемент Wikidata, статті якого вимірюються в усіх мовах аналізу; **проксі** - виміряна тема, ширша або вужча за тему питання.
- **Не оцінено** - мовні розділи, для яких немає даних за весь запитаний період: немає пов'язаної статті, коротка історія статті або нульова база.
  Вони показуються окремо і ніколи не ранжуються з оціненими: це не низька увага.
- **Рекомендація щодо наступного дослідження** (`investigate_next`, `consider`, `lower_priority`) - інтерпретація моделі, а не рішення про запуск продукту.

## Архітектура

### Потік

```
питання користувача
  → агент: аргументи analyze.ts
  → analyze.ts: тема → QID Wikidata → статті в мовах → історичні назви → перегляди → метрики → analysis.json
  → агент: conclusion.json (лише інтерпретація, без чисел)
  → report.ts: перевірка conclusion.json → report.pdf
  → агент: відповідь у чаті за фіксованим шаблоном
```

Ключові принципи:

- **Код рахує, модель інтерпретує.**
  Пошук теми, дані, метрики, надійність тренду, графік і PDF робить детермінований код.
  Модель перекладає питання в аргументи, обирає тему з кандидатів і пише висновок без чисел.
  Усі числа в PDF рендеряться з `analysis.json`, а `report.ts` відхиляє висновок з цифрами, неоціненими мовами чи задовгим текстом і пояснює, що виправити.
- **Помилки для моделі.**
  Кожне `Error:` каже, що змінити, щоб дешева модель могла виправитися сама; вивід `analyze.ts` - компактний JSON з `next_step`.
- **Одна тема - один QID.**
  Статті в різних мовах знаходяться через Wikidata, а не перекладом назви; перегляди статті включають її колишні назви, підтверджені журналом перейменувань.
- **Відтворюваність.**
  Точні версії залежностей у `package-lock.json`, без скомпільованих файлів; тести й evals працюють офлайн на збережених відповідях Wikimedia.

### Файли

```
wikipedia-interest/
├── SKILL.md                  # інструкції для агента
├── README.md                 # цей файл
├── .claude-plugin/plugin.json # маніфест: тека - single-skill плагін для claude plugin eval
├── package.json, package-lock.json, .npmrc, tsconfig.json
├── assets/fonts/             # Noto Sans (OFL): латиниця, кирилиця, грецька
├── scripts/
│   ├── analyze.ts            # крок 1: аргументи → analysis.json
│   ├── report.ts             # крок 3: analysis.json + conclusion.json → report.pdf
│   └── lib/
│       ├── cli.ts            # розбір аргументів, UserError і вихід з помилкою
│       ├── env.ts            # тека навички, змінні EVAL_WIKI_INTEREST_* для тестів і evals
│       ├── http.ts           # fetch з User-Agent, повторами, файловим кешем і офлайн-режимом
│       ├── wikipedia.ts      # спільні запити до MediaWiki API
│       ├── resolve.ts        # тема → QID, кандидати з coverage, статті в мовах
│       ├── history.ts        # історичні назви статті через журнал перейменувань
│       ├── pageviews.ts      # перегляди статті й мовного розділу
│       ├── period.ts         # запитаний період: --start, --end, --months
│       ├── metrics.ts        # чисті функції: відносна увага, зміни, тренд, надійність, прапорці
│       ├── analysis.ts       # формат analysis.json і MAX_LANGUAGES
│       ├── conclusion.ts     # перевірка conclusion.json
│       ├── chart-geometry.ts # чиста геометрія графіка
│       ├── chart.ts          # рендеринг графіка примітивами pdfkit
│       ├── pdf.ts            # верстка однієї сторінки A4
│       ├── glyphs.ts         # перевірка покриття символів шрифтом
│       └── strings.ts        # фіксовані тексти звіту українською й англійською
├── tests/                    # node:test; fixtures/ - збережені відповіді Wikimedia
├── evals/                    # кейси claude plugin eval на Claude Haiku 4.5
└── docs/
    ├── PLAN.md               # план MVP і журнал рішень
    ├── ROADMAP.md            # як розвивати навичку далі
    └── AI-VERIFICATION.md    # як використовувався і перевірявся AI
```

Джерела даних: [Wikimedia Pageviews API](https://doc.wikimedia.org/generated-data-platform/aqs/analytics-api/reference/page-views.html) (помісячно, `all-access`, лише `agent=user`), MediaWiki API і Wikidata.
Чому саме так - у [журналі рішень](docs/PLAN.md#журнал-рішень).

## Розробка

```
npm ci
npm run typecheck   # tsc --noEmit
npm test            # офлайн: CLI на фікстурах, метрики, геометрія графіка, SKILL.md, evals
npm run smoke       # живі smoke-тести: три приклади запитів проти реального Wikimedia API
```

`npm test` не ходить у мережу; `npm run smoke` щоразу стартує з порожнього кешу і перевіряє лише те, що не залежить від свіжих даних.
Повний сценарій на дешевій моделі запускається через `claude plugin eval`, команди й результати - в [AI-VERIFICATION.md](docs/AI-VERIFICATION.md).
